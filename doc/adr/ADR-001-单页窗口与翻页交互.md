# ADR-001: 选人界面排版工具 —— 单页窗口与翻页交互

- **状态**: Accepted (2026-09-07)
- **日期**: 2026-09-07
- **范围**: 选人界面排版工具/select-layout-tool.html 单文件

## Context

工具当前将整个 layout (例 840×4100, 7 页) 连续滚动展示, 导致:
1. item 拖动后位置 大致正确但有偏差 —— 用户报告无法精确对齐游戏内位置
2. 大文件时画布需要滚动条, 视野跨页, 不直观
3. 没有翻页概念, 必须滚轮滚很久

## Decision

### 1. 窗口尺寸: 固定 800×600 视口, 整体居中

- main 区域右上角始终显示一个 800×600 的舞台框
- layout.width/height 不论多少, 整体等比缩放至 800×600 完整显示
- 缩放比 = min(800/layout.width, 600/layout.height)
- item 坐标按比例映射: 屏幕位置 = (item.x * scale + offset.x, item.y * scale + offset.y)
- 居中: 若 layout.width < 800 则左右补白; 同理 height

**注**: 这一项会带来屏幕像素 ≠ xml 数值的换算, 拖动时鼠标位置需反算回 xml 坐标写入 offset.

### 2. 翻页粒度: 可自定义, 默认 PAGE_HEIGHT=600

- state.PAGE_HEIGHT: 数字 input (顶部栏 + 段 1), 范围 [100, 2000], 默认 600
- 修改 PAGE_HEIGHT 时, 自动重新计算总页数 totalPages() = ceil(layout.height / PAGE_HEIGHT)
- 总页数变化时, currentPage 按比例保留 (例: 之前第 4 / 7 页, 改 PAGE_HEIGHT 后尽量保持相对位置)
- currentPage (0-based): 当前显示第几页
- 顶部右侧显示「第 N / M 页」(例: 第 4 / 7 页)

### 3. 翻页操作:

| 触发 | 行为 |
|---|---|
| 滚轮 | 跨页边界 → 翻页; 同页内 → snap 不动 |
| 滚动条拖动 | snap 到页边界 (0 / PAGE_HEIGHT / 2*PAGE_HEIGHT / ...) |
| ↓ / PageDown / Space | 下一页 (currentPage++, 最大 M-1) |
| ↑ / PageUp | 上一页 (currentPage--, 最小 0) |
| Home | 第 1 页 (currentPage=0) |
| End | 最后一页 (currentPage=M-1) |
| 顶部按钮: « ‹ › » | 同上 |
| 输入框聚焦时 ↑↓ ←→ | 微调 1px / Shift+方向键 = 10px (现有行为保留) |

### 4. 越界判定:

- 屏幕坐标超出 [0,800]×[0,600] 才视为越界 (与当前 1:1 像素坐标不同, 改为视口坐标)
- 越界仍画虚线轮廓 + OUT 角标

## Alternatives Considered

- **A: 仅顶部翻页按钮** — 弃, 键盘党不友好
- **B: 840×4100 不缩放, 仅显示当前页 800×600 区域** — 弃, 4-7 页的 item 因画布高度 4100 而被裁掉, 不直观
- **C: 翻页粒度固定 600** — 弃, 改为可配置 (本决策 §2)

## Risks

- **R1**: 缩放换算误差 → 拖动精度问题加剧; 解决: scale 取自 layout 比例, 反算用 Math.round
- **R2**: 现有 verify 脚本里 canvas.width/height = layout.width/height 的断言会失败; 解决: 改 pplyCanvasSize 让 canvas 物理像素 = 800×600 (不变布局), 渲染时按 scale 映射; 更新 verify 断言
- **R3**: undo 栈里的 state 不含 currentPage/PAGE_HEIGHT, 跨页撤销可能错位; 解决: 加入 snapshot
