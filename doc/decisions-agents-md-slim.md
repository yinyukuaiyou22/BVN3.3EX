# AGENTS.md 精简决策记录（2026-11-02）

> **背景**：`AGENTS.md` 130 行，与 `CLAUDE.md`、`doc/README.md`、`doc/runtime-pitfalls.md` 存在多处重复副本；且它第 95 行指向被 `.gitignore` 忽略的 `.agents/`，违反自己第 13 行的自维护规则。
> **决策方式**：/grill-me 细问 3 轮。本文件只留**结论 + 理由 + 被否决选项**；执行台账见 git log（基线 tag `snapshot/pre-agents-slim-2026-11-02-1034`）。

## D1 正文骨架 = 目标 / 约束 / 冲突后的优先级

- **结论**：`AGENTS.md` 只保留三节骨架 + 开工序列 + 指针块。
- **理由**：三段顺序本身就是「一段常驻注入该长什么样」的合同，比原来七节拼盘更容易判断某条内容该不该留。
- **否决**：把这三条只当筛内容的评判标准、保留原分节——精简会退化成措辞修剪。

## D2 细则落点 = 新建 `doc/agent-rules.md`

- **结论**：被下沉的内容进独立文件，`AGENTS.md` 只留指针。
- **理由**：`doc/README.md` 自称「`doc/` 的唯一目录」，让它兼任手册会复现同一退化路径。
- **否决**：全塞进 `doc/README.md`（索引变第二本手册）；并入 `doc/runtime-pitfalls.md`（工程规则塞进运行时踩坑，语义错位）。

## D3 行数 = ≤70 行，硬上限 90

- **结论**：实测落点 **69 行**（原 130），自维护上限从 200 收到 **90/70**。
- **理由**：只做去重、不删任何硬规则就到 69 行；上限仍留 200 会让压缩成果被逐次涨回。
- **否决**：≤100（留不住）；≤60（会开始牺牲硬规则措辞精度）。

## D5 冲突优先级 = 两层，不压成单链

| 层 | 排序（左高右低） |
|---|---|
| **指令层** | 用户当前指令 > `AGENTS.md` > 技能/workflow 说明 > `doc/` 专题 > 代码注释 |
| **证据层** | 实测/日志/可运行代码 > `CLAUDE.md` > `doc/` 专题 > `doc/archive/` 与历史文档 |

- **理由**：压成单链必然得出「`CLAUDE.md` 无条件最高」，而它确实会过时（`AI-SYSTEM-DOC.md` 的基准路径 `BVNscripts/PC/` 已不存在）。
- **推论**：证据层冲突时以「跑一遍看到了什么」为准，并顺手修正 `CLAUDE.md`；规则不推翻事实，不许按文档想象改代码。

## D6 删 `.agents/` 指针而不是改 `.gitignore`

- **否决**：从 `.gitignore` 摘掉 `.agents/`、让技能包入库——那是上游技能会覆盖的目录，指针随时失效；而四条工作流约束是文本，不依赖它存在。

## D7 工作流四约束改写为文本规则

- **结论**：判定表 + 四条硬约束写进 `agent-rules.md` §5，不再写「阶段数以该 SKILL.md 为准」。
- **理由**：技能目录未入版本库，克隆后不存在；把规则托管给一个可能消失的文件是新的单点。

## D8 git 快照 = 定向快照，不全量扫脏树

- **结论**：开工前打 `snapshot/pre-<主题>-<日期>` tag；一个逻辑单元一次 commit（本轮 4 个）；**只提交本次涉及的路径**。
- **理由**：工作区当时有 72 项脏改动（46 个 `.as` 是 TAG 半成品，另有 `_map_sheets/`、`_missing.json`、`__pycache__/` 等临时产物）。全量快照（沿 `676a786` 的做法）会把别人的半成品与临时产物一起定版，与 `.gitignore` 治理方向相反。
- **否决**：git add -A 全量基线。

## 环境事实（本轮实测，供后续复用）

1. **pwsh 写 `doc/`、`.git/` 被拒绝**，而备用写入通道正常 → git add/commit 必须用一次放宽权限的调用重试；这不是仓库损坏，是文件权限层。
2. **pwsh Get-Content 会把 UTF-8 中文按 GBK 解码**：同一份 69 行的 `AGENTS.md`，它数出 52 行、内容出现乱码并吞掉换行。→ 中文文件的读写与校验一律用 Node 读原始字节，Get-Content 的 .Count 不能作为行数判据。
