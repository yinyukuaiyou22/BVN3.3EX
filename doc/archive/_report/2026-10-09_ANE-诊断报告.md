## 三、#2113 到底是什么意思（运行时取证）

从 APK 内 `lib/arm64-v8a/libCore.so`（AIR 51.0.1.1 运行时，20.9 MB）提取到的原始字符串：

```
'Provided parameter LoaderContext.SecurityDomain is from a disallowed domain.'
'Provided parameter LoaderContext.ApplicationDomain is from a disallowed domain.'
'flash.external:ExtensionContext'
'_createExtensionContext'
'ExtensionContextClass'
'ExtensionContextObject'
```

即：AIR 内部用 `Loader` 加载扩展的 AS3 `library.swf` 时，构造的 `LoaderContext`
其 `securityDomain` 被 AVM2 判定为「不允许的域」，直接抛 #2113。

同时提取到扩展加载器的诊断/校验字符串：

```
'Loading extension %s on %s - SWF data %p'          ← 日志里出现的那条
'The SWF version for library.swf in extension ' ... ' is invalid. It is less than 10'
'The extension ' ... ' has either a namespace version or library.swf with a version
  that is incompatible with the applications namespace or root SWF.'
'Extension namespace is invalid for '
'm_extDirIsAppBundled' / 'isDefaultAppDeployedExtensionDir' / 'isDefaultDeviceDeployedExtensionDir'
'Native Extensions: ignored because directory does not contain an extension.xml file '
'Application requires extensions, but extensions are not supported in this profile of AIR.'
```

**注意**：上述「SWF version / namespace 不兼容」诊断**没有出现在 logcat 里** →
说明版本/命名空间校验是通过的。

### 已逐项排除的假设

| 假设 | 实测结果 |
|---|---|
| ANE 没打进 APK | ❌ 排除：`assets/META-INF/AIR/extensions/com.bvn.filereader/` 完整，`classes.dex` 含全部 `com/bvn/filereader/*` |
| ANE 结构不对 | ❌ 排除：与 `ANEToolkit.ane`（可用）逐项一致 —— mimetype、catalog.xml、合成 `_flash_display_Sprite` 类、APK 内布局 |
| dex 版本不兼容 | ❌ 排除：class major version = 52（JDK8），d8 正常转换 |
| extension.xml 命名空间非法 | ❌ 排除：32.0 在运行时支持的扩展命名空间表内（2.5…51.0） |
| **SWF 版本 / 命名空间不兼容** | ❌ 排除：launch.swf v37、library.swf v37、应用 ns 32.0、扩展 ns 32.0，且诊断日志未触发 |
| `<extensions>` 未进打包后的描述符 | ❌ 排除：APK 内 `assets/META-INF/AIR/application.xml` 保留 `<extensionID>com.bvn.filereader</extensionID>` |
| **调用太早（route A）** | ❌ **证伪**：19 秒内 4 次尝试全失败 |

## 四、AABPackager 崩溃根因（顺带查明）

之前把描述符命名空间改成 51.0 时 ADT 报 `AABPackager.createPackage` 异常。
本次拿到完整堆栈：

```
at org.gradle.wrapper.Download.downloadInternal(Download.java:83)
at com.adobe.air.apk.AABOutputStream.buildGradle(AABOutputStream.java)
at com.adobe.air.apk.AABPackager.renameOutput(AABPackager.java)
at com.adobe.air.ApplicationPackager.createPackage(ApplicationPackager.java)
at com.adobe.air.apk.AABPackager.createPackage(AABPackager.java)
```

**根因**：AIR 51 的 ADT 在 **51.0 命名空间**下会走 AAB（Android App Bundle）打包路径，
而该路径需要**联网下载 Gradle wrapper**；离线环境必然失败。

**验证**：构造 `appA.xml`（ns 51.0 + 移除 `<extensions>`）单独打包 ——
**依然同样崩溃** ⇒ 与 ANE 完全无关。

⇒ **结论：本机离线环境下只能用 32.0 命名空间描述符**（走 legacy `APKPackager`）。

### 连带发现
32.0 描述符 + legacy packager 下，**ANE 的 `Android/AndroidManifest.xml` 不会被合并进 APK 清单**：

```
APK AndroidManifest.xml 中搜索 'BVNDataFilesProvider' / 'BVNDataFilesWakeUpActivity'
→ utf8: 0, utf16: 0   （完全不存在）
```

即 legacy packager 对 ANE 的支持是**不完整**的（provider/activity 未合并）。
这与 #2113 是否同源未定，但方向一致：**32.0 legacy 打包路径对 ANE 的处理存在缺陷**。

## 十、关键发现：命名空间 ↔ SWF 版本一致性（新的头号嫌疑）

### 10.1 修正：此前"`extension/31.0` 不存在"是**错误结论**
之前用正则扫 `airsdk.xml` 时写错了标签（`<version>` vs `<descriptorNamespace>`），
只扫到 0 条，于是误判"31.0 缺失、32.0 是下限"。**完整表已用
`tools/Test/inspect_ane.py` 输出**，`extension/2.5 … 32.0, 33.1, 50.0, 50.1, 50.2, 51.0` 全部存在。

关键行（两个 SDK 一致）：

| 命名空间 | swfVersion |
|---|---|
| `application/26.0` / `extension/26.0` | **37** |
| `application/31.0` / `extension/31.0` | 42 |
| `application/32.0` / `extension/32.0` | **43** |
| `application/33.1` / `extension/33.1` | 44 |
| `application/51.0` / `extension/51.0` | 51 |

### 10.2 本项目当前的**三方版本不一致**

| 项 | 现值 | 按 airsdk.xml 应对应 |
|---|---|---|
| `application.xml` 命名空间 | `application/32.0` | swf **43** |
| `launch.swf` 编译参数 | `-swf-version=37` | `application/26.0` |
| `extension.xml` 命名空间 | `extension/32.0` | swf **43** |
| ANE `library.swf` 编译参数 | `-swf-version=37` | `extension/26.0` |

即：**描述符声明的版本 ≈ AIR 32，实际编译出来的 SWF ≈ AIR 26**，两侧各差 6 个版本。

### 10.3 ADT 的硬约束（实测报错，重要）
把应用命名空间降到 26.0（意图与 swf 37 对齐）时，ADT 直接拒绝打包：
```
Included native extension 'com.bvn.filereader' specifies namespace
'http://ns.adobe.com/air/extension/32.0' which is greater than the
application namespace: http://ns.adobe.com/air/application/26.0
```
⇒ **ANE 的 extension 命名空间必须 ≤ 应用命名空间**。
所以"只改 `application.xml`、不动 ANE"是不合法的。

### 10.4 因此只剩两条**自身一致**的候选路线

- **路线 D1（降命名空间，改动小）**
  `extension.xml` → `extension/26.0`；`application.xml` → `application/26.0`；
  所有 SWF 保持 `-swf-version=37`。
  三方全部对齐到 swf 37，**不需要重编 35 MB 的 launch.swf**。
  已实测：ADT **接受**打包（`probe_bvn26b.apk`，8.88 MB）。

- **路线 D2（升 SWF，改动大）**
  保持 `application/32.0` + `extension/32.0`，把 SWF 全部重编到 `-swf-version=43`。
  需要动 `build.bat` / `mxmlc` 编译参数并全量重编。

> 提醒：D1 会改变应用命名空间（AIR 32 → AIR 26）。若后续要用到 AIR 27+ 才有的
> 描述符特性需复核；但对本项目现有描述符字段（`supportedProfiles` / `renderMode` /
> `manifestAdditions` 等）均在 AIR 26 支持范围内。

- `bvn` 失败、`bvn26b` 或 `bvn43` 成功 → **命名空间/SWF 版本不一致就是根因**，
  直接把对应改动搬到主工程即可。

## 十三、ANE Java 源码审计（回答"Java 是否有问题"）

### 13.1 结论：Java 源码**不可能**是 #2113 的原因

五条独立证据：

1. `E/BVNFileReader: initialize() called` 出现在 logcat → AIR **确实**加载并初始化了原生库；
2. `createContext() called extId=...` **一次都没出现** → AIR **从未**走到 Java 的上下文工厂；
3. 抛错点是 `_createExtensionContext()`，这是 AS3/原生层，**先于** `FREExtension.createContext()`；
4. **完全无关的第三方 ANE（ANEToolkit）报一模一样的错**，它的 Java 实现与我们的毫无共同点；
5. 换 Adobe 原版 AIR 33.1.1、加减 `supportedProfiles`、4 组命名空间/SWF 组合，行为完全一致。

⇒ 只要 `createContext()` 不被调用，`getFunctions()` 里那 9 个 FREFunction 一行都不会执行。

### 13.2 但源码确实有真实缺陷（与 #2113 无关，属清理项）

- **`BVNDataFilesProvider`（599 行）整套是死代码**：SAF DocumentsProvider，向外暴露
  `/data`、`/data/user_de`、`/data/obb`、`android_data`，还带 MT 管理器私有的
  `mt:setLastModified` / `mt:setPermissions` / `mt:createSymlink`。
  但 `<provider>`/`<activity>` 在 `tools/Test/application.xml:30-35` 被注释掉，
  ADT 32.0 的 legacy 路径**也不会**把 ANE 的 `AndroidManifest.xml` 合并进 APK 清单
  （实测清单里搜不到 `BVNDataFilesProvider`），AS3 侧 `registerProvider()` **0 处调用**。
  ⇒ 这条链路从 APK 清单到调用点，**全断**。
- **`getExternalFilesDir(subPath)` 的 `subPath` 参数被完全忽略**，函数返回的是
  `externalFilesDir` 的**父目录**；AS3 包装也只传 `""`。
- **`Log.e` 被用在正常路径**（`initialize() called`、`createContext() called`），
  应为 `Log.d`；release 包里 `Log.e` 是唯一能进 logcat 的级别，会污染日志。
- **`createContext(String extId)` 不校验 `extId`** —— 传错 ID 也会返回一个 context。
- `import java.io.IOException;` 未使用。
- ANE 的 AS3 类 `BVNFileReaderLib` **在整个工程中 0 处引用**，它存在只是为了让 compc
  产出一个非空 `library.swf`；其中 `readBytes/listDir/...` 这些包装方法全是死代码。
- `extension.xml` 里的 `<platform name="default">` 是 C1 试验残留，ADT 在
  Android-ARM64 目标下会丢弃该目录，**不产生任何效果**。
