## 2. 自维护规则（全文）

`AGENTS.md` 曾从 770 行退化过一次，根因是缺这几条。改它、或改本文件的人必须遵守：

1. **行数上限**：`AGENTS.md` 硬上限 **90 行**、目标 **70 行**；本文件 300 行。超了按主题继续下沉，**不准为凑行数删内容**。
2. **准入清单**：`AGENTS.md` 只放**跨批次有效、违反即出事**的规则。批次性记录、某一次修复的经过、某个 swf 的字节数，一律进 `doc/` 或本文件。
3. **禁止写入**：`.backup` 文件名清单、编译产物 md5/字节数、密钥与证书路径、设备序列号、**已被 `.gitignore` 忽略的目录里的指针**（如 `.agents/`、`.claude/`）。
4. **改了 `CLAUDE.md` 的事实也要回头看 `AGENTS.md`**：两份文件的指针必须始终指向真实存在且未被忽略的路径。
5. 新专题文档一律放 `doc/`，并同步更新 [`doc/README.md`](README.md)。

> 第 1–3 条已提炼为 `AGENTS.md` §2 末尾的「本文件自身的准入」，两处必须同步改。

## 4. 分支策略

| 分支 | 用途 | 远程 |
|---|---|---|
| `master` | 完整开发版（含实验功能） | `mobile`（3.3BVNmobile） |
| `公开部分` | 公开稳定版 | `origin`（BVN3.3EX） |

公共 bug 修复先提交到 `master`，再 cherry-pick 到 `公开部分`。

## 5. 复杂改动的工作流

**何时启用**（满足任一即启用）：

| 场景 | 启用 |
|---|---|
| 单文件小修 / 已有明确方案且 ≤2 文件 | 否，直接改 |
| 新功能 / 新模块 / 跨层修改 | **是** |
| ANE / 构建脚本 / 打包流程变更 | **是** |
| 重构 / 多文件联动 / API 接口变更 | **是** |

**四条硬约束**（文本自足，不依赖任何技能文件）：

1. 先有 `doc/<feature>/proposal.md`（目标/成功标准/待决问题）再写码。
2. 每个任务 ≤3 个文件，完成后 `git diff` 审查 + `./build.bat`。
3. `progress.md` 是唯一真相源（状态/阻塞/跑过的命令）。
4. AI 输出在通过编译 + diff 审查前**只算草稿**。

> 本地若有工作流技能包（`.agents/skills/vibe-coding-workflow/`），其阶段数以该 SKILL.md 为准；但该目录被 `.gitignore` 忽略，克隆后可能不存在——**上面四条约束不依赖它**。
