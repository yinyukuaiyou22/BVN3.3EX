# select.xml 分页清洗 + 默认内嵌 修复计划

## Repository Research

### 问题现象
工具打开 select.xml 后，"第二页的内容出现在第一页底部"——截图中可见第一页除了正常显示的前 5 行外，底部还有 2 行越界显示。

### 根因分析（已通过脚本验证）

**char_list（人物页）** 的 row offset `y` 值存在两类错误数据：

| 类型 | 示例 | 影响 |
|---|---|---|
| 累积行距漂移 | row 0→6 的 y=0, 20.54, 41.08, 61.62, 82.16, 102.7, 149.24 | 行距不均匀，部分行微越界到下一页窗口 |
| 大幅负跳变 | row 6→7 的 y 从 149.24 跳到 164.78（差 15.54），部分行后续出现 -2822、-446.67 等极端负值 | 直接把本应在后续页的行拉回到 page 0 渲染窗口 [0, 600) 内 |

当前 item 渲染坐标公式：`y = startY + gapY * gridY + offset.y`，offset.y 本应是微调量（±几 px），但 XML 里写成了绝对值/累积值，导致渲染位置完全偏离预期分页。

**assist_list（辅助页）** 的负 offset（-433, -880, -1327...）是**有意设计**——它用于抵消 gapY=506.67（13 行 × 6300px 分摊）的稀疏，把 item 压缩到合理分页。**不动它**。

**isOnCurrentPage** 用的是"相交判定"（item 顶部在窗口内但底部超出 → 仍会被画），导致底部越界 item 被截断渲染。但清洗 XML 后这个问题会自然消失（每行行距均匀，底部不会跨窗口）。

### 清洗前后分页对比

**char_list 清洗前**：
- item 渲染 y 范围：60 ~ 8508（maxBottom=9035）
- 15 页，每页 8~10 行，**几乎每页底部都有越界行**

**char_list 清洗后**（row offset y 归零）：
- item 渲染 y 范围：60 ~ 5999
- 11 页，每页 13~14 行，**无越界**
- assist_list 保持现状（2 页：8+5 行）

## Files and Modules

| 文件 | 改动 |
|---|---|
| `选人界面排版工具/解析素材/select.xml` | 清洗 char_list 的 row offset y → 0；浮点噪声（2.84e-14、-1.13e-13、2.27e-13）→ 0 |
| `选人界面排版工具/select-layout-tool.html` | 替换 `<script id="default-xml">` 内嵌的默认 XML 数据为清洗后的版本 |

**不改**：assist_list 的任何内容（row offset、item offset、offset 值）。

## Implementation Steps

### Step 1 — 备份
- `.backup/select-layout-tool.html.<timestamp>`
- `.backup/select.xml.<timestamp>`

### Step 2 — 编写清洗脚本并运行（临时，用完即删）
用 Node.js 处理 select.xml：
1. 解析 XML
2. 遍历 char_list 的所有 `<row>` 元素
3. `row.setAttribute('offset', 'x,0')` — 保留原 X，Y 置 0
4. 遍历 char_list 和 assist_list 的所有 `<item>` 元素
5. 若 item offset 含极小浮点噪声（abs < 0.01 且为科学计数法或接近 0 的浮点），清零
6. 写出 XML，保持原缩进风格

### Step 3 — 替换 HTML 内嵌默认数据
1. 读取清洗后的 select.xml 全文
2. 找到 `select-layout-tool.html` 中 `<script type="application/xml" id="default-xml">` 标签
3. 替换标签内容为清洗后的 XML（去掉 `<!-- Generated by ... -->` 注释行，保持与现有内嵌格式一致）

### Step 4 — 验证
- Node.js 分析脚本跑清洗后数据 → char_list 11 页每页 13 行、assist_list 2 页 8+5 行
- 无越界（每页最底 item 的 bottom 均 ≤ 该页 pageBottom）
- HTML 打开后 char_list 正确加载清洗后数据

## Dependencies and Considerations

- **XML 格式**：保持与原文件一致的 tab 缩进、属性顺序、大小写
- **assist_list 不动**：它的负 offset 是对抗 gapY 稀疏的有意设计
- **layout 参数不动**：x=-23, y=0, width=900, height=6300, left=10, right=20, top=60, bottom=110
- **item offset 不动**：只动 row offset；item 级 offset 可能是有意的微调

## Validation

| 检查 | 方式 | 预期 |
|---|---|---|
| char_list 分页 | 分析脚本 | 11 页，每页 13~14 行，无越界 |
| assist_list 分页 | 分析脚本 | 2 页（8+5），不变 |
| XML 合法性 | DOMParser | 无 parsererror |
| HTML 内嵌数据 | 字符串比对 | 与清洗后 XML 一致 |
| 工具打开 | 手动/脚本 | 无 JS 报错，char_list 渲染干净 |

## Risks

| 风险 | 处理 |
|---|---|
| char_list 部分 row offset y 是有意微调而非漂移 | 清洗后如果视觉上某行位置不对，可针对性恢复微调量；当前数据漂移模式（递增均匀、突变、大负值）均非微调特征 |
| 内嵌数据替换时遗漏某个 item | 脚本精确处理 + 清洗前后行数比对（应保持 138 行） |
| XML 缩进被 DOMParser 序列化改变 | 手工保留原缩进风格（读原 XML → 正则替换 row offset y → 写回） |
