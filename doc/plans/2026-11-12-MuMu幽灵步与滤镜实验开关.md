# MuMu 幽灵步黑幕与手机滤镜实验开关（2026-11-12）

## 1. 目标与批准范围

以当前工作区源码为基线，先在 MuMu 模拟器复现、保留证据，再修复；不因「怀疑换人模式」预先改状态机。

1. 角色正常使用幽灵步时，概率停在黑幕且无法操作；验证普通模式与换人模式（16/17），确认是否与换人改动有关。
2. 钢身闪光后可能残留上色、位图／元件矩形范围，而非正常透明滤镜结果；用连续截图区分染色、轮廓辉光、全屏闪光、代理位图，不凭颜色猜根因。
3. 手机常规设置新增「滤镜效果（实验功能）」开关，**默认关闭**，APPLY 保存，重启仍保持。关闭通用 GPU 滤镜代理与钢身轮廓滤镜；战斗逻辑、判定、普通无滤镜技能动画不变。
4. 开启滤镜的兼容问题仍修，PC 行为不变。验收以 MuMu 的实际操作、截图和日志为准；未复现的故障只能标「未确认」，不能报「已修复」。

非目标：调整换人操作、无敌时长、幽灵步消耗／时停／数值；重做设置布局、美术或其他设置项；宣称覆盖其他真实手机；顺手整理无关脏树。

**Change Necessity**：旧存档没有该选项，旧 GPU_FILTER_PROXY 也不控制钢身独立视图，因此只改文档或既有画质档位不够。最小代码边界是复用 ConfigVO → applyConfig → GameConfig/FilterProxyManager/EffectCtrl 现有链路；幽灵步与显示故障只在证据指到的现有 owner 内修，不新增第二套状态机。

**TDD Route**：mode=off，decision=skipped（未获严格 TDD 授权）；测试姿态为修改前复现 + 修改后针对性回归。通过条件见 §6，不以编译通过替代功能验收。

## 3. 任务 1：冻结证据基线并复现幽灵步

**涉及**：FighterMcCtrler.as、FighterEffectCtrl.as、EffectCtrl.as、TagModeCtrler.as、GameCtrl.as、Debugger.as；仅在确有需要时改它们。

1. 确认 MuMu 在线且 ADB 明确选中它；不依赖自动选设备。记录已安装 APK／新构建 SWF 的 BUILD_TAG，保证日志、截图、二进制配套。保留当前外置素材与存档；如打包脚本会移动外置目录，先记录并确保可恢复，不能用精简包结果冒充完整包。
2. 在**未加入本轮修复**的版本，分别在普通战斗、TAG 地面与空中情境下正常操作幽灵步；对照「只幽灵步」「幽灵步与空中换人相邻发生」。记录角色、模式、操作次序、滤镜开关状态、复现次数／尝试次数；不得为了复现而注入无限气、跳过正常冷却或改黑幕逻辑。
3. 同时间窗保留连帧截图和 logcat／私有日志；二进制截图通过安全重定向输出，避免 PowerShell 文本重定向损坏 PNG。证据放 tools/Test/_report/，不提交账号、设备标识或存档内容。
4. 观察 EffectCtrl.ghostStep/endGhostStep 的两类 just-render 登记、世界 pause/resume、黑幕 parent、地图 visible，以及 TAG 的 freeze start/end 与 _tagFreezeIng。核对 FighterMcCtrler._ghostStepFrame 是否在 justRenderAnimate 中归零、是否提前离场或触发另一条结束链。现有日志缺哪一项，才加最小低频探针，受 Debugger 开关控制。
5. 若复现：将「黑幕仍在 + 世界未恢复 + 对应状态未结束」形成同一时间轴，再确定唯一根因。若未复现：如实记录样本和缺口，只保留必要的低频诊断，不修改幽灵步逻辑。

**通过条件**：得到普通模式与 TAG 对照结果；若修复，至少一段修复前证据能解释黑幕为何未结束。

## 4. 任务 2：接入手机滤镜实验开关

**涉及**：ConfigVO.as、GameInterfaceManager.as、GameConfig.as、FilterProxyManager.as、EffectCtrl.as；SettingState.as 应复用而不改，除非实测证明契约不通。

1. ConfigVO 增加默认 false 的布尔配置，纳入 toSaveObj() 和旧存档读取；字段缺失时保持 false，其他配置不变。APPLY 时由既有 GameInterfaceManager.applyConfig() 应用，避免把画质档切换重设为 true。
2. 在常规设置的画质附近加入「滤镜效果（实验功能）」和开／关选项，沿用触控滚动、选择与 APPLY，不改行距、列宽、颜色或其他选项。
3. 手机运行时以新配置决定通用代理和钢身轮廓滤镜是否启用；PC 保持既有 GPU 代理行为，不能全局硬编码为 false。钢身状态位、受击、命中染色与全屏非滤镜闪光仍属战斗效果，不借开关改写其状态机。
4. FilterProxyManager 关闭时取消待处理工作、回收全部代理并恢复被隐藏的源节点，保留正常 alpha／visible／色变换所有权；不能只停扫描，留下 alpha=0 的源。开启时重新走现有注册／预算机制。
5. EffectCtrl.startFilter() 是钢身轮廓视图现有入口；关闭时不创建、且回收现存视图。切换中不得复制／重建状态机、误清黑幕或普通技能效果。
6. 验证：默认安装与无字段旧存档＝关；改开但不 APPLY＝不持久化；APPLY 后重启＝开；关后重启＝关。连点开关、设置页进出和战斗中效果结束均不产生隐藏源、旧位图或不可见角色。

**Repair / Retirement**：保留原 GPU 兼容实现供手动开启，不删除或替换另一套滤镜路径；退役的是「手机端无条件开启」这一默认行为。旧 GPU_FILTER_PROXY 保留为运行时控制，但权威配置只能来自新开关，不引入第二个存档字段。

**通过条件**：默认关闭的实际游戏画面正常；切换立即清理／恢复滤镜，APPLY 与重启保持，其他画质选项和 PC 默认值不变。

## 5. 任务 3：按证据修钢身滤镜残留与矩形显示

**涉及候选**：SteelHitEffect.as、FighterEffectCtrl.as、EffectCtrl.as、BitmapFilterView.as、FilterNodeProxy.as、FilterProxyManager.as、FighterMain.as。只改被证据命中的 owner。

1. 在任务 2 的开关**开启**时复现，以关闭态作画面／逻辑对照。连帧区分：SteelHitEffect 的 RGB 偏移、钢身 BitmapFilterView 的轮廓、全屏 ShineEffectView、TAG alpha 闪烁、通用代理 Bitmap。
2. 若染色残留：对照 freeze 结束回调是否执行、目标是否已离场／重开，以及 FighterMain.resumeColor() 恢复的是角色原 CT 还是默认 CT；在现有生命周期清理中修，不用覆盖所有颜色效果的硬复位。
3. 若矩形／不透明底：核对 KyoUtils.drawBitmapFilter 输出与 alpha 通道、滤镜 bounds／外扩、缩放／翻转、位图销毁与回收。BitmapFilterView 现按动画帧号缓存，要检查内容／透明度／滤镜变化时是否错误复用旧图；不得以「矩形」直接猜 bounds。
4. 若通用代理残留：检查源 alpha=0 的还原、代理清理、真实 alpha 含 0 的读回，以及关闭／离场／重开的回收。通用代理不要再次 applyFilter 造成双重滤镜。
5. 每项修复保留前／后同机位截图、关键日志和实际根因；不能以关闭开关后的正常画面证明开启态已修复。

**Repair / Retirement**：优先修现有回收／同步逻辑，不加永久看门狗或第二 owner 掩盖症状。已有清理路径保留；若确需新增路径，必须写明触发条件及旧路径为何不能覆盖。

**通过条件**：钢身／灵爆／换人和重开后，角色颜色与透明度正确，无残像、无矩形底，普通透明图正常；关闭滤镜时战斗状态与判定不改变。
